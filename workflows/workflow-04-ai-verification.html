AI Document Verification

Planned: automated document verification using AWS Textract OCR (Rekognition face matching deferred)

Workflow Goal

Automatically verify uploaded CP Driver documents — CDL, Insurance, Vehicle Registration, and Inspection/Safety — using AWS AI services. Extract text from documents using OCR (Textract) and validate document authenticity/expiry. This reduces manual verification time and improves accuracy.

⚠ Not implemented today. As documented in workflow-03-documents.html, there is currently no OCR/AI pipeline wired up at all — everything in this file describes a planned integration, not shipped behavior. Documents sit at Document.status: 'pending' until an admin manually approves or rejects the whole driver (workflow-05-driver-approval.html).
⚠ Face-match / selfie verification is deferred, not just unimplemented. The CP Driver onboarding redesign does not collect a driver profile photo/selfie anywhere in the flow (see workflow-02-profile.html) — so there is nothing to compare a license photo against. The Rekognition face-matching sections below are kept for historical/design reference only; they describe a feature that is out of scope until profile photo capture is added to onboarding, not a feature that currently works or is close to working.

Implementation Flow (proposed — not built)

Written against a future state where document storage has moved to S3; today it's local disk (see workflow-03-documents.html).

  1. Document uploaded (docType: cdl / insurance / vehicle_registration / inspection), webhook/event triggers Lambda function
  2. Lambda retrieves the document file
  3. AWS Textract analyzes document for text extraction
  4. Parse OCR results per docType — CDL number/name/DOB/class/expiry (cdl); policy number/expiry (insurance); VIN/plate (vehicle_registration, cross-checked against the linked Truck); inspection date (inspection)
  5. Calculate confidence scores for each field
  6. If driver photo exists, trigger AWS Rekognition face comparison — deferred, no driver photo is collected in this onboarding flow (see caveat above)
  7. Update Document with AI verification results
  8. Send notification to driver with results
  9. If confidence {'>'} 80%, mark for admin review; if {'<'} 80%, flag for manual verification

Business Rules (proposed — not enforced today)

  • OCR Confidence Threshold: Minimum 70% confidence for auto-approval
  • Face Match Threshold: N/A — deferred, no driver photo/selfie collected in this onboarding flow
  • Manual Review: Any score below threshold requires admin review
  • Processing Time: AI verification completes within 2 minutes
  • Retry Logic: Automatic retry up to 3 times on AI service failure
  • Data Validation: Extracted expiry date must be future date
  • Cost Control: Use AWS Lambda for serverless, pay-per-use model

Security Considerations (proposed — not built)

  • IAM Roles: Lambda has minimum permissions for S3 and AI services
  • Encryption: All data encrypted in transit and at rest
  • Audit Logging: All AI operations logged in CloudWatch
  • Data Privacy: AI results stored separately, PII encrypted
