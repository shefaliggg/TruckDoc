🔄 Profile Management

View and update user or driver profile information

📋 Workflow Goal

Allow users and drivers to view and update their profile information, including personal details, contact information, and role-specific data (like driver license information). This workflow ensures data accuracy and enables users to manage their account settings.

Scope note: The India-market content below (GST numbers, Aadhaar/PAN, +91 numbers) describes the legacy TruckUser/TruckDriver profile. CP Shipper (US, vcg_user) uses the lighter, US-market onboarding flow in the next section instead — it runs immediately after CP Shipper auth (workflow-01-auth.html) and is intentionally much shorter than CP Driver onboarding (workflow-01-auth.html, workflow-03-documents.html, workflow-05-driver-approval.html): a driver has to prove a person + CDL + truck + compliance before receiving loads; a shipper only needs to establish person/company + contact + basic billing/shipping identity before booking one.

🇺🇸 CP Shipper — Onboarding (Profile Creation)

Runs right after CP Shipper phone/email + OTP authentication. Kept deliberately light: only what CP needs to identify the customer, establish the shipping account, and enable booking — not shipment preferences, saved routes, or payment details, which are collected just-in-time at first booking.

Create Account (Phone / Email — see workflow-01-auth.html) ↓ Phone / Email Verification (OTP) ↓ Your Information (first name, last name, phone, email) ↓ Individual / Business (account type) ↓ Business Information (Business accounts only) ↓ Primary Shipping Location (optional — can be skipped, set later per shipment) ↓ Terms & Agreements ↓ Shipper Home

Screens

  • Your Information: First name, last name, phone, email — pre-filled from whichever method (phone or email) was used to sign up; the other one is entered here.
  • What type of shipper are you? Two options — Business or Individual. Determines whether the Business Information screen is shown.
  • Business Information (Business accounts only): business/company name, business address, city, state, ZIP code, business phone/email. No EIN or other tax ID field at signup — see "What's deliberately deferred" below.
  • Primary Location: pickup/ship-from address, city, state, ZIP — has a visible Skip action; shipments can specify a different pickup address later per booking.
  • Terms & Agreements: CP Terms of Service, Privacy Policy, and the shipping/customer agreement (if applicable) — checkboxes or a single combined acceptance, required to continue.

What's deliberately deferred (not asked during onboarding)

  • Payment / billing: billing name, billing address, and payment method are collected just-in-time at the shipper's first booking/payment (workflow-06-create-booking.html, workflow-12-invoice.html), not made mandatory at signup.
  • EIN / business tax information: only collected later if the payment, billing, or compliance workflow actually requires it — not a mandatory onboarding field.
  • Shipment preferences, favorite routes, preferred truck types, driver preferences
  • Multiple pickup or delivery locations (one optional primary location only)
  • Marketing preferences, extra company contacts
  • Any document not required for CP's specific operating model

All of the above can be collected later, typically when the shipper creates their first booking — this keeps Create Account → first booking friction to a minimum.

🇺🇸 CP Driver — Onboarding (Driver Information + CDL Information)

Runs right after CP Driver email OTP authentication (workflow-01-auth.html). Driver.onboardingStep drives which screen a driver lands on when relaunching the app mid-onboarding. This section covers the first two steps in detail — Driver Information and CDL Information. The remaining steps (Qualification, Truck Information, Truck Documents, Agreements) are covered in workflow-03-documents.html and workflow-05-driver-approval.html.

Create Account / Log In (Email OTP — see workflow-01-auth.html) ↓ Driver Information (name, date of birth, address) onboardingStep: driver_info ↓ CDL Information (CDL #, state, class, endorsements, expiry, CDL photo) onboardingStep: cdl_info ↓ Qualification (experience, medical cert, MVR consent, road test) onboardingStep: qualification ↓ Truck Information (unit #, VIN, plate, make/model/year) onboardingStep: truck_info ↓ Truck Documents (registration, insurance, inspection, op. authority) onboardingStep: truck_documents ↓ Agreements (ToS, Privacy Policy, Driver Agreement, MVR consent) onboardingStep: agreements ↓ Submitted → Pending Admin Review (see workflow-05-driver-approval.html)

Screens (this section)

  • Driver Information (onboarding/DriverInformationScreen.jsx): first name, last name, date of birth, address (line 1, city, state, zip).
  • CDL Information (onboarding/CdlInformationScreen.jsx): CDL number, issuing state, class — A/B/C selectable chips, endorsements — H/N/P/S/T/X multi-select chips, expiration date, and a CDL photo/PDF upload.

🔌 API Endpoints

CP Shipper Onboarding (US)

GET /api/shipper/profile

Get current shipper profile + profileStatus (drives resume-onboarding)

PUT /api/shipper/profile/basic

Save Your Information (first/last name, phone, email)

PUT /api/shipper/profile/account-type

Set accountType ('individual' | 'business')

PUT /api/shipper/profile/business

Save Business Information — only called when accountType = 'business'

PUT /api/shipper/profile/primary-location

Save (or skip) the primary shipping location

POST /api/shipper/profile/accept-terms

Record termsAcceptedAt; marks profileStatus = 'complete' and unlocks Shipper Home

CP Driver Onboarding — Driver Information + CDL Information (actual implementation)

GET /api/drivers/me

requireAuth + requireRole('driver'). Returns the current driver, populated with truckId, plus a documents array pulled from the Document collection.

PUT /api/drivers/me/driver-info

JSON body. Saves first/last name (on User) and date of birth + address (on Driver). Advances onboardingStep from 'driver_info' to 'cdl_info'.

PUT /api/drivers/me/cdl-info

Multipart (file field cdlDocument — JPG/PNG/PDF, 8MB max). Saves CDL number, issuing state, class, endorsements, expiry; uploads the CDL photo as a Document (docType: 'cdl'). Advances onboardingStep to 'qualification'.

PUT /api/drivers/:driverId/availability

Update driver isOnline status — own profile only (403 if driver.userId doesn't match the authenticated user)

PUT /api/drivers/me/bank

Update bank details. Body key is now routingNumber (US ACH) — renamed from the old ifscCode.

The remaining onboarding-step endpoints (/me/qualification, /me/truck-info, /me/truck-documents, /me/agreements) are documented in workflow-03-documents.html.

⚙️ Implementation Flow

Profile View Flow

  1. User navigates to profile screen
  2. App sends GET request to /api/users/me or /api/drivers/me
  3. Backend verifies JWT token and fetches user/driver data
  4. Response includes profile data with related information
  5. Frontend displays profile in view mode with edit option

Profile Update Flow

  1. User taps "Edit Profile" button
  2. Form loads with current profile data pre-filled
  3. User modifies fields and submits form
  4. Frontend validates input (email format, phone format, required fields)
  5. App sends PUT request with updated data
  6. Backend validates and updates database record
  7. Success response triggers UI update and success message
  8. User returned to view mode with updated information

Availability Toggle (Drivers)

  1. Driver toggles availability switch
  2. App sends PUT to /api/drivers/:driverId/availability with { isOnline }
  3. Backend updates the isOnline field (own profile only — 403 otherwise)
  4. If unavailable, driver excluded from trip assignments
  5. Status reflected in admin dashboard

📐 Business Rules & Validation

  • Email Uniqueness: Email must be unique across all users
  • Phone Validation: Phone number must be valid Indian format (+91...)
  • License Validation: License number format must match state standards
  • License Expiry: Drivers with expired licenses cannot accept new trips
  • Document Verification: Profile changes don't affect verification status
  • Email Change: Email changes require verification via confirmation email
  • Password Change: Requires current password for security
  • Admin Override: Admins can edit any profile but changes are logged
  • Data Retention: Old profile data retained for 90 days for audit
  • Availability Auto-Reset: Driver availability resets to available after 30 days inactive

🔒 Security Considerations

  • JWT Authentication: All profile endpoints require valid JWT token
  • Role-Based Access: Users can only edit their own profiles
  • Admin Authorization: Only admins can edit other users' profiles
  • Password Hashing: Passwords never returned in API responses
  • Data Sanitization: All inputs sanitized to prevent XSS/injection
  • Rate Limiting: Profile updates limited to 5 per hour per user
  • Audit Logging: All profile changes logged with timestamp and user IP
  • Sensitive Data: License numbers and documents encrypted at rest
